# GDD Prototype (Updated)

## 1) High Concept

- Игра в духе `Karryn's Prison` по тону и тематике (gender bender NSFW).
- Core loop: забег в формате `Vampire Survivors-like` -> остановка/результат -> база-stub -> следующий забег.
- Главная цель героя: спуститься в подземелье, победить Короля Демонов и вернуть изначальный облик.

## 2) Зафиксированный Scope MVP

- `1` боевая карта.
- `1` полный run длительностью `3 минуты`.
- `3` архетипа врагов: `melee`, `ranged`, `caster`.
- `6` перков уровня (пул на выбор).
- `4` пассивки поражения.
- База полностью `stub`: только переходы и сохранение ресурсов после забега.
- Графика обязательна на уровне системы: загрузка и рендер текстур/спрайтов, включая placeholder-изображения.

## 3) Подтвержденные правила геймплея

### 3.1 Состояния игрока
- Две шкалы: `HP` и `Arousal`.
- `HP <= 0` -> проигрыш -> возврат на базу -> выдача пассивки поражения.
- `Arousal >= 100` -> **тоже проигрыш** (Вариант A) -> возврат на базу -> выдача пассивки поражения.

### 3.2 Правила run и остановки
- Run длится `3:00`.
- Внутри run есть волны; после убийства последней волны появляется экран остановки.
- На остановке:
  - `Continue` (следующий уровень, в MVP можно оставить как заглушку),
  - `Exit to Base` (легальный выход с забега).
- Экономика выноса ресурсов:
  - выход через остановку: `100%` собранных ресурсов,
  - проигрыш (HP/Arousal): только `30%` собранных ресурсов.

### 3.3 Враги
- `melee`: преследует игрока и наносит контактный урон.
- `ranged`: держит дистанцию и стреляет тонким снарядом.
- `caster`: стреляет снарядом другого вида (например, визуально толще), чтобы читалась отдельная роль.

### 3.4 База (строго stub)
- Никакого строительства/апгрейд-дерева в MVP.
- На базе доступны только:
  - начало нового забега,
  - отображение результата прошлого забега,
  - сохраненный общий ресурс.

### 3.5 Good/Bad ending
- Для MVP логика good/bad ending и влияние пассивок на концовки **вынесены за scope**.
- Данные пассивок сохраняются, но сюжетные ветвления пока не реализуются.

## 4) Предложенные численные параметры (v0.1 для старта прототипа)

### 4.1 Игрок
- `HP max`: `100`
- `Arousal`: `0..100` (старт `0`)
- Скорость движения: `220 px/s`
- Автоатака:
  - интервал: `0.55 s`
  - урон: `16`
  - дальность: `260 px`

### 4.2 Враги (базовые)
- `Melee Grunt`: HP `40`, контактный урон `8`, speed `140 px/s`, hit cooldown `0.9 s`
- `Ranged Archer`: HP `30`, projectile damage `7`, projectile speed `280 px/s`, attack cooldown `1.4 s`
- `Caster`: HP `50`, projectile damage `10`, projectile speed `230 px/s`, attack cooldown `1.8 s` (снаряд визуально толще)

### 4.3 XP и уровни
- XP за убийство:
  - melee `10`
  - ranged `12`
  - caster `16`
- Порог следующего уровня:
  - `XP_to_next = round(40 * level^1.25)` для `level >= 1`
- На каждом уровне показывается выбор из `3` случайных перков.

### 4.4 Пассивки поражения (пример для MVP)
- `Fractured Nerves`: +10% входящего урона по HP
- `Sensitive Skin`: +15% входящего arousal-урона
- `Heavy Steps`: -8% скорость движения
- `Shaky Focus`: +12% интервал автоатаки

Примечание: выдавать `1` случайную пассивку за каждый проигрыш.

### 4.5 Перки уровня (пул 6 шт.)
- `Power I`: +15% урон
- `Attack Speed I`: -12% интервал атаки
- `Vitality I`: +20 max HP (и heal до нового max)
- `Calm Mind`: -20 мгновенного arousal
- `Momentum`: +10% speed
- `Range I`: +18% дальность атаки

## 5) Данные, которые сохраняются между забегами

- `totalResource` (общий накопленный ресурс).
- `lastRunResourceRaw` и `lastRunResourceGranted`.
- список полученных `defeatPassives`.
- статистика: количество забегов, поражений по HP, поражений по Arousal.

## 6) Техрешение по SFML 2.6.2 (углубленный выбор)

### 6.1 Рекомендованный подход
- Система сборки: `CMake` + `CMakePresets.json`.
- Основная dev-конфигурация: **MSVC (`SFML-2.6.2-windows-vc17-64-bit`)**.
- Дополнительная проверка совместимости: MinGW (`SFML-2.6.2-windows-gcc-13.1.0-mingw-64-bit`).

Почему так:
- MSVC на Windows проще интегрируется с Visual Studio debugger и стабильнее в повседневной разработке.
- MinGW оставляем как второй таргет, чтобы не потерять поддержку GCC-сборки.

### 6.2 Как подключать обе версии
- В пресетах задаются разные генераторы и `SFML_DIR`:
  - MSVC preset -> `SFML_DIR=../SFML-2.6.2-windows-vc17-64-bit/lib/cmake/SFML`
  - MinGW preset -> `SFML_DIR=../SFML-2.6.2-windows-gcc-13.1.0-mingw-64-bit/lib/cmake/SFML`
- В `CMakeLists.txt`:
  - `find_package(SFML 2.6 COMPONENTS graphics window system REQUIRED)`
  - линковка через `SFML::Graphics`, `SFML::Window`, `SFML::System`.

### 6.3 DLL стратегия (обязательная для запуска)
- Для каждого пресета после сборки копировать нужные DLL из соответствующего `SFML/bin` в папку `.exe`.
- Для MinGW дополнительно проверить наличие runtime DLL компилятора (`libstdc++-6.dll`, `libgcc_s_seh-1.dll`, `libwinpthread-1.dll`) в PATH или рядом с `.exe`.

### 6.4 Что выбрать как "официальный" путь MVP
- Официальный путь MVP: `Windows + MSVC`.
- MinGW статус: `supported (best effort)` с регулярной проверкой сборки.
- Это снижает риски сроков, но сохраняет дву-тулчейнную совместимость.

## 7) Definition of Done (MVP)

Прототип готов, если:
- работает цикл `Base(stub) -> Run(3 min) -> Stop/Defeat -> Base`;
- `HP` и `Arousal` независимо приводят к поражению;
- при поражении начисляется только `30%` ресурсов run;
- при выходе на остановке начисляется `100%` ресурсов run;
- работает XP/уровень/выбор перка;
- применяются и сохраняются пассивки поражения;
- все сущности отображаются через систему спрайтов (включая placeholder assets);
- проект собирается и запускается в MSVC пресете, MinGW пресет собирается без критических правок кода.
